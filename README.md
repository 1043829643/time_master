# 时间管理大师

温润极简的个人工作空间：项目全景、并行事项、日程、推进看板、联系人、工程位置，以及 Qwen 语音助理。

## 代码管理

项目仓库：[1043829643/time_master](https://github.com/1043829643/time_master)，主分支为 `main`。Git 仅保存源码、配置模板与测试；密钥、本机数据库、依赖和构建产物均通过 `.gitignore` 排除。

## 运行

需要 Node.js 22.13+。安装依赖后执行 npm run dev。使用 React / Vinext、Cloudflare Worker 与 D1；生产数据按登录用户隔离。首次本地使用先生成并应用 drizzle/ 中的数据库迁移，持久目录为 .wrangler/state。

## Qwen 配置

支持北京地域百炼通用接口（QWEN_ACCESS_MODE=standard）及 Token Plan 专用接口（QWEN_ACCESS_MODE=token-plan）。本机原有 token-plan-local 配置作为兼容别名保留。

在忽略的 .dev.vars 中配置与 .env.example 一致的变量：QWEN_API_KEY、QWEN_ACCESS_MODE、QWEN_CHAT_MODEL、QWEN_ASR_MODEL、QWEN_TTS_MODEL、QWEN_VOICE。Site 的变量独立配置；QWEN_API_KEY 使用 Sites secret，其余模型设置使用环境变量。不要把凭证写入源码或浏览器。

通用接口默认模型：qwen-plus（对话与安排方案）、qwen3-asr-flash（语音识别）、qwen3-tts-flash（中文朗读）。本机 Token Plan 测试使用 qwen3.8-flash、qwen-audio-3.0-asr-flash、qwen-audio-3.0-tts-plus，音色 longanhuan_v3.6。浏览器录音在本机转为 16kHz 单声道 WAV 后提交。识别文本可编辑，安排方案需要检查后应用；没有密钥时明确显示未配置。

## 数据行为

- 任务周期允许并行；只有具体日程时段检查冲突。AI 方案按整批修改后的最终日程检查，包括方案内部重叠。
- 项目全景提供全程导航、统一比例的可缩放时间轴与今天定位；短事项不会被压成负宽度。
- 日历区分可推进和等待条件的事项，完整列表可展开，保留暂停、等待和前置未完成的原因。
- 事项超出项目周期时，项目日期自动扩展。
- 编辑保存使用打开时的记录基线做字段级三方合并。不同记录、不同字段可自动合并；同字段相异修改展示双方内容并逐项选择，合并后仍整体校验日期和依赖。草稿保存在当前标签页，关闭编辑器和刷新可恢复；关闭整个标签页不承诺保留。保存时锁定表单。
- 所有保存经过同一服务端流程：读取最新工作空间、合并、重算冲突和删除影响、确认后 CAS 原子提交。确认期间业务再次变化必须重新核对。删除基线包含关联记录，避免旧删除操作误删后来加入的内容。
- 聊天始终读取服务器最新工作空间；回复、方案基线与重试回执在同一事务中保存。网络中断后重试取回原回复，不重复追加消息。生成期间无关业务改变不会令独立方案失效。
- 待确认方案持久保存在服务端，关闭、刷新、继续闲聊后可恢复；两份独立方案可以连续应用。应用内容取自服务端原方案，与方案状态原子提交。早期无基线方案仍保留业务版本保护。
- 日程冲突说明由程序根据实际操作计算，避免模型摘要自相矛盾；前置延期和等待条件直接显示在已排日程上，事项完成后可确认释放未来预留时间。跨项目依赖在全景中明确列出。
- Qwen 每轮通过工具区分答复与方案，无效结果自动纠正一次，仍失败时保留输入并明确提示。
- 长回复按句子分段生成并连续朗读，支持随时停止，不静默截断。
- 切回页面、其他标签页保存以及页面可见期间每 30 秒自动同步；断网和同步失败明确显示状态。未发送文字保留在当前浏览器标签页，刷新后可继续。失败录音单独保存在当前浏览器的 IndexedDB，可刷新后重试或下载；朗读和聊天不会清除录音的恢复入口。浏览器禁止存储时明确降级为当前页暂存。等待回复时可以停止等待，输入及原请求编号保留供重试。
- 删除事项或项目会解除依赖、移除未完成且未固定的日程；已完成及固定日程保留为独立记录，并在确认前列明固定安排。实际电脑文件和共享联系人不删除。
- 工程路径和微信号为上下文记录，不会自动访问本地文件或发送消息。
- 示例由用户主动载入；托管站点首次进入为空工作空间。本地测试数据不上传。

- 事项自身改期后检查已有日程是否超出预计范围；待确认方案与全部其他待确认方案对照，放弃后刷新提示。模型上下文有字符预算，冲突明细有展示上限。
- 失去原记录的草稿可以从统一入口找回、复制、另存为新记录；缺失项目必须重新选择，不能自动落到其他项目。
- 支持恢复旧版或新版 JSON 备份：补缺失或完整独立副本，先预览再确认。独立副本重建关联，项目日期扩展明确提示；使用专用原子事务和持久回执防止重复恢复，不受普通编辑 60 项限制。聊天和当前历史保留，最多 8 MB。
- 更早聊天按回执分页读取，用户问题与回答成对显示；已应用和已放弃方案的讨论仍可查阅。显式重新整理方案使用新请求，网络重试保留原请求。

## 持久化与同步约束

- 工作空间按项目、事项、日程、联系人、资源、消息与历史分行存储。工作空间主记录只保留版本和元信息，避免整个工作空间或大方案撞上 D1 单值限制。每次修改只写变化记录，SQL 参数按字节分块；业务数量与备份 8 MB 上限仍有效。
- 原有整包数据在首次访问时用单个事务迁移；失败全部回滚，下次可重试。迁移后触发器拒绝旧服务重新写入整包数据，防止滚动发布期间破坏新结构。
- 保存、记录变更、操作回执和方案状态通过同一事务提交。提交令牌隔离每次 CAS 尝试；持久回执不会随最近 100 次操作列表淘汰。已提交但响应丢失时，先查询原结果；未提交的旧请求先关闭，再允许新修改，防止迟到请求落盘。继续改稿仅重放用户本次变化，保留上次合并到的其他设备内容。
- 删除校验使用关联范围的 SHA-256 摘要，保留完整并发保护，同时避免把整项目说明塞进删除请求。已有旧格式方案仍可读取。
- 对话回执携带提交序号。更早历史与新消息追赶使用不同游标；追赶固定版本、按序分页，失败保留进度。工作空间最近消息仅用于即时显示，不能宣称缺口已经补齐。放弃方案也更新同步版本，但不增加业务版本。
- 录音按工作空间隔离；录音 ID 所有权和消费回执阻止不同标签覆盖、删除或复活旧录音。支持 Web Locks 的浏览器串行处理同一工作空间的识别；识别文字写入输入草稿后再清理音频。录音恢复是当前浏览器能力，不是云端录音同步。

实现入口：`lib/workspace-storage.ts`、`lib/chat-parts.ts`、`app/use-assistant-sync.ts`、`app/use-speech-input.ts`。新增或调整写操作时必须复用统一提交路径，不得直接回写工作空间整包。
