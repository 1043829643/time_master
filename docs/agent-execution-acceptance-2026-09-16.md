# 2026-09-16：Agent 执行与连续输入验收

本次针对已确认方案落地执行闭环，仍保留「今天 / 项目全景」两个主入口。

## 已实现

- 明确、无冲突的新增或修改直接执行；预览零业务写入；自然确认应用原方案及原编辑基线。涉及删除、固定安排变化或新冲突时，呈现具体影响后再应用。
- 请求在调用 Qwen 前持久记录。回复、业务记录、操作回执、方案状态及记忆转换同一事务提交；租约、取消与工作空间版本共同阻止迟到写入。
- 执行卡可读取实际变更并撤销。撤销逐字段合并，恢复原先不存在的可选字段，保护后来新增的关联对象与其他字段；新冲突必须重新核对。
- 聊天发送先入持久队列，可以继续输入下一条。稳定请求编号、同步入队去重、跨页执行锁、取消栅栏与不存在不回写，防止双击、断线重试、取消后复活。
- 草稿与交接按工作空间隔离。随手记整理和跟进改期保留字段、原记录、目标编号与未确定保存结果；成功后同步清理暂存。
- 未约定时间的跟进可直接记录，不算逾期、不导出虚假提醒；精确硬截止约束自动排程，截止后的错误预留不抵扣截止前工作。
- 部分否定明确排除旧子项；追加说明必须保留原文；资料等待由跟进关系表达，避免重复手动等待。预览记忆暂存，应用时激活、撤回时遗忘。

## 验证证据

- 128/128 自动回归通过，含 14 项新增真实 SQLite 事务、撤销、租约、记忆和场景规则检查；TypeScript 检查通过。
- 12 轮连续真实 Qwen 对话全部 HTTP 200，逐轮检查保存状态和最终记录。10 轮执行、1 轮仅预览、1 轮只读。没有依靠手工补种项目继续测试。
- 12 轮耗时中位数 9.00 秒，范围 3.20–22.49 秒。耗时为本地实测，不是服务承诺。
- 真实浏览器连续发送两条补充，连按 Enter 只生成两个不同请求；刷新后恢复跟进表单。初次快速输入测试暴露异步入队期间第二次发送无响应，已改成串行入队，再测通过。
- 实测 1440px 桌面、390px 手机宽度；手机主区域和助手均为390px，输入框在屏内，无横向溢出，浏览器无运行错误。
- 真实撤销工程迁移和联系人备注更新后，同编号重试返回同一次撤销，其他日程保留。
- 真实 Qwen TTS 返回268,844字节音频，转成16kHz后交给真实ASR，识别为「明天下午3点，不对，改成4点到4点半，帮我留半小时看初稿。」没有使用或验收用户本人麦克风。
- 真实对话发现模型曾同时产生跟进阻塞与task.waiting；已加服务器规则并补回归。预览转自然确认、归档保留原文、同一日程连续改期、路径迁移与备注追加均检查了最终数据。
- 本地 local_seedy 测试数据已恢复：10张按用户隔离的表逐项核对，其他用户数据一致；生产数据未用于本轮故障测试。

## 尚需持续验收的边界

- 这组验收不能证明所有自然语言都能一次理解正确。歧义、多份方案指代与冲突仍需就地澄清。
- 网络与供应商可能失败；已落实的是原话和回执恢复，不是永不失败。不同设备各自未发送的草稿仍留在本机。
- 本轮没有完成长期数月使用、真实用户多口音麦克风、容量上限与长期服务耗时的全部验收；原设计中的这些条目仍是后续测试基线。
- 不代发微信、不移动电脑文件；工程操作修改的是项目中的位置记录。关闭网页后的提醒仍通过系统日历导出。
